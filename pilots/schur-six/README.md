# Six colors, no monochromatic sums

**Package:** 1.0.0, verified September 7, 2026 (Pacific).  
**Status:** Baseline and checker package ready for pilot seeding; no live challenge has been created by this work.  
**Research target:** A six-coloring of 1,...,N with N >= 537 and no same-color solution of x+y=z, including x=y.

This package reproduces the published S(6) >= 536 construction of Harold Fredricksen and Melvin M. Sweet. It does not claim a new lower bound or an exact value of S(6). A July 2026 research paper still uses 536 as the established lower bound. [Original publication](https://www.combinatorics.org/ojs/index.php/eljc/article/view/v7i1r32), [recent research](https://arxiv.org/html/2607.15034v1)

## Verify the baseline

From the repository root, using Python 3.10+ or Node 18+:

```text
python pilots/schur-six/verify.py pilots/schur-six/baseline-536.json
node pilots/schur-six/verify.mjs pilots/schur-six/baseline-536.json
```

Both checkers use only their language's standard library. They read data; they do not execute submitted artifacts. Successful verification exits 0. An invalid witness or format exits 1. A CLI/file error exits 2.

The canonical artifact's SHA-256 is:

```text
968f91177ddf7cbe9ce0347c8f2be089c54a6b648c387a6080cbec1237636010
```

It is compact UTF-8 JSON with an LF final newline. Color labels are 0 through 5. Class sizes are **129, 86, 110, 77, 64, 70**. The Python checker examines all **71,824** unordered pairs x<=y with x+y<=536. The Node checker uses a different algorithm: bitset intersections of each color class with its translates.

## Provenance

Page 6 of the original paper lists a compressed construction. It is expanded using reflection x -> 537-x, except that **179 stays in paper Set 4 and 358 stays in paper Set 1**. This exception follows the symmetry convention on page 2; blindly mirroring those two entries would corrupt the witness.

The page was inspected visually, and every listed integer was compared with the corresponding page of the independent NPS-hosted copy. `source-transcription.json` preserves the listed sets. `build_baseline.py` deterministically reconstructs the canonical artifact. `provenance.json` records source URLs, source hashes, page numbers, decoding rules and the independent encoder comparison. The publisher PDF is retained under `sources/` for inspection, with its author attribution intact.

## Checker validation

`validation.json` records **25,764 case evaluations with zero failures** across the two implementations:

- All 9,330 six-colorings at lengths 1 through 5, checked against a separate sumset oracle.
- 300 deterministic random cases.
- All 536 prefixes of the published witness.
- All 2,680 single-label changes to that witness. The oracle accepts 94 of these; the tests do not assume that every mutation is invalid.
- 36 raw JSON and format cases, including duplicate/escaped keys, booleans, integral and fractional numbers, UTF-8 errors, wrong lengths, oversized inputs and both equal and unequal summands.

The baseline was also checked against **all 439,520 clauses** generated by Marijn J. H. Heule's independently authored `Schur-encode.c` with arguments `6 536`. Every clause is satisfied. That source was downloaded from its author's university page, fully inspected, then compiled locally; it is not vendored here. This is an independent encoding cross-check, not a SAT search or an UNSAT proof. [Heule's reference tools](https://www.cs.utexas.edu/~marijn/Schur/)

```text
python pilots/schur-six/build_baseline.py
python pilots/schur-six/test_verifiers.py --output validation-replay.json
```

To reproduce the third-party encoding check, retrieve the encoder URL and verify its hash from `provenance.json`, inspect it, compile it with a C compiler, and run it with `6 536`, saving its output as `Schur_536_6.cnf`. Then pass `--reference-cnf <path>` to `test_verifiers.py`. CNF byte hashes may differ by platform line endings; the test checks the variables, complete clause count and every clause under the supplied coloring.

Both packaged checkers were written in this Astra session. Their implementations and the sumset oracle differ, but that is not independent-operator review. The external encoder provides separately authored corroboration. The finite test suite is not a formal proof of the checkers' correctness.

## Artifact contract

Only these root fields are allowed: `format_version`, `n`, `colors`. Version is 1; n is an integer from 1 to 10,000; the array has exactly n integer values in 0,...,5. JSON numeric values such as 1.0 are accepted when mathematically integral; booleans are not numbers. Duplicate keys, non-JSON constants, invalid UTF-8 and files over 1 MiB are rejected. See `artifact.schema.json`; its shape checks alone do not establish a valid Schur witness.

All six colors need not be used. The prefix must be contiguous from 1. A valid artifact establishes S(6) >= n. It is eligible for a new-bound claim only when it exceeds the frozen baseline and survives a fresh novelty check. Near-colorings with forbidden sums are experiment logs, not lower-bound certificates.

The 10,000-element cap is an operational limit of this pilot format. Do not treat an out-of-format rejection as a mathematical counterexample. Verification runs on contributors' or reviewers' machines, never automatically on the board's Worker.
